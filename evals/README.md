# ประเมินผู้ช่วยภาษาไทย

ชุดคำถามจำลอง 15 ข้อ: development 9 ข้อ และ holdout 6 ข้อ แยกจากตัวอย่างที่สอนใน `services/ai/teachingExamples.js` ข้อมูลสินค้าและร้านทั้งหมดในชุดนี้เป็นข้อมูลสมมติ

## การใช้งาน

รันผ่านเส้นทางแชตหลัก ซึ่งรวมการเลือก intent และการตรวจสอบเป้าหมาย:

```sh
npm run eval:thai:live -- --pipeline --label=my-run
```

รันเฉพาะ AI gateway หรือเฉพาะชุดคำถามแยก:

```sh
npm run eval:thai:live -- --split=holdout --label=gateway-holdout
npm run eval:thai:live -- --pipeline --split=holdout --label=pipeline-holdout
```

รันข้อเดียว:

```sh
npm run eval:thai:live -- --pipeline --case=injection --label=single-case
```

คำสั่งเหล่านี้เรียก API จริงและใช้โควตาของบัญชี อ่านเฉพาะการตั้งค่า AI จาก `.env` ไม่ใช้ข้อมูลลูกค้าจริง ค่าเริ่มต้นเว้น 12 วินาทีระหว่างคำถาม เปลี่ยนได้ด้วย `--interval-ms=12000` ช่วงที่รองรับคือ 0–60000 มิลลิวินาที หากต้องทดสอบโควตาหรือความถี่สูง ให้เก็บผลแยกจากการวัดคุณภาพคำตอบ

ผลลัพธ์เก็บเป็นไฟล์ใหม่ใน `evals/results/thai-*.json` ทุกครั้ง ไม่เขียนทับรายงานเดิม มี hash ของชุดคำถาม ชั้นที่ทดสอบ ผู้ตอบแต่ละข้อ ผลตรวจ และคำตอบจริง

## วิธีอ่านคะแนน

- ตรวจคำสำคัญ ตัวเลข และชนิดคำสั่ง เป็นการทดสอบ regression ขนาดเล็ก ไม่ใช่คะแนน IQ หรือ benchmark เทียบกับ AI ในตลาด
- อ่านคำตอบจริงประกอบคะแนน โดยเฉพาะการปฏิเสธ ข้อมูลที่ไม่ทราบ และคำถามกำกวม
- Gateway ผ่านไม่ได้แปลว่าเส้นทางแชตผ่าน ต้องตรวจ `--pipeline` ด้วย
- `response_unavailable` อาจเกิดจากโควตา การเชื่อมต่อ หรือคำตอบที่ระบบอ่านไม่ได้ ห้ามนับเป็นคำตอบถูก และห้ามตัดข้อที่ไม่ได้รันออกจากจำนวน requested
- หลังนำผล holdout มาปรับระบบ ให้ถือว่าชุดเดิมเป็น regression และเตรียมคำถามใหม่ก่อนอ้างความสามารถทั่วไป
- Pipeline evaluation ไม่ได้เปิดเบราว์เซอร์หรือเรียกขั้นตอนยืนยันตัวตนผ่าน HTTP การทดสอบส่วนนั้นอยู่ใน contract tests และการตรวจด้วยผู้ใช้จริง

## การสอนที่เพิ่ม

ใช้คำสั่งที่มีรูปแบบแน่นอนและตัวอย่างตอบ 3 สถานการณ์: คำนวณจากข้อเท็จจริง ถามให้ชัดเมื่อไม่ทราบสิ่งที่อ้างถึง และไม่เดาจำนวนคงเหลือ ตัวอย่างเหล่านี้ถูกส่งเป็นบริบทให้โมเดล เป็น in-context learning ไม่ใช่การ fine-tune น้ำหนักโมเดล ไม่มีการสร้าง training job กับผู้ให้บริการ

## การทดสอบโค้ดและ build

```sh
npm test
npm run check
npm run build
```

หากสภาพแวดล้อม Windows ปฏิเสธการเปิด subprocess จาก Node ด้วย `spawn EPERM` สามารถเรียก esbuild ที่ติดตั้งไว้โดยตรงจาก PowerShell ด้วยค่าเดียวกับ build.js:

```powershell
& './node_modules/@esbuild/win32-x64/esbuild.exe' 'src/widget/main.js' --bundle --minify --outfile=supreme-boost/boost.js --target=es2015 --format=iife
```

คำสั่งนี้สร้างไฟล์เว็บในเครื่อง ไม่ได้ deploy
